## 受付・プロフィール

`StructuredIntakeAnswers` の18項目を入力し、`pet.structured` として保存・AI入力へ同じ内容を渡す。選択肢はモック準拠。任意自由記述と旧登録の読み取り互換を保持する。

新規受付では `{ version: '2026-09', accepted: true, acceptedAt }` の同意を保存する。AIへ送る健康・行動情報、氏名・連絡先の除外、写真と音声を含まない動画抽出静止画の処理を説明する。

7軸は `personalityAxes` にある0〜100の保存値だけ表示する。旧5軸からの換算や未回答の自動補完はしない。

## StaffApp接続

| props | 責務 |
|---|---|
| `pets` | 全登録犬。プロフィールと当日選択に使用 |
| `operationDate` / `onOperationDateChange` | 運営日の選択と再取得 |
| `dailyOperation` | 保存済み対象犬・日付・revision・最新案ID |
| `roomSettings` | 保存済み施設部屋とrevision |
| `currentPlan` | 当日headが参照する案のみ |
| `auditEntries` | 保存された操作監査 |
| `onSaveDailyPets` / `onSaveRooms` | 入力値の保存。Appが担当ID/revisionを補完 |
| `onOptimize` | 保存済み対象と施設部屋で再計算 |
| `onDecidePlan` | 最新案をconfirmed/rejectedへ遷移。理由を引き渡す |
| `onObserve` | 手動事実を保存し、必要な同室不可更新と再計画を実行 |

既存の `confirmed` / `onConfirm` は `currentPlan` / `onDecidePlan` に置換する。相性・マップ・観測の犬候補はStaffAppで保存済み当日選択に絞る。Appは当日に有効な計算結果だけを渡す。

承認待ちは `isCurrentProposed(day, rooms, plan)` が成立する0件または1件。旧日付なし履歴やstaleな案を数えない。部屋の手動割当は今回の対象外。

## 観測・表示

手動観測は `source: manual`、操作担当、対象犬、運営日を伴う実保存記録だけを当日進行に反映する。過去のデモシナリオを手動観測に変換しない。カメラ実接続、周期実行、動画保管、実通知は今回の対象外。

相性はパーセントで表示し、同室不可の明示制約を別表示する。未定義の段階判定や固定AI説明は追加しない。監査は担当・日時・操作・理由・案参照を表示する。

## 委任

ユーザー指定のモデル・強度に合わせ、3名とも `default / gpt-6-astra / high`。固定モデルを持つ通常の役割指定より明示指定を優先した。

- `owner_structured_ui`: 受付・同意・7軸を一貫して扱うため。
- `daily_operations_ui`: 当日選択・部屋設定・承認却下を同じ編集状態で扱うため。
- `observation_compat_ui`: 手動記録と当日進行、相性表記を統一するため。

親はStaffApp接続、統合確認、Git共有を担当する。
