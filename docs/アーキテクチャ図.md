## サービス接続

~~~mermaid
flowchart LR
    Hosting[Firebase Hosting]
    App[Reactアプリ<br/>飼い主フォーム・スタッフ画面]
    Auth[Firebase Auth<br/>施設ログイン]
    DB[(Cloud Firestore<br/>施設・招待・受付・提案・観測)]
    Worker[Cloudflare Workers Free<br/>入力検証・秘密鍵保持]
    Orca[OrcaRouter<br/>構造化分析]
    Hosting -->|静的アプリ配信| App
    App <-->|施設認証| Auth
    App <-->|Rulesでアクセス制御・保存・読戻し| DB
    App -->|構造化入力・一時画像| Worker
    Worker <-->|AI解析| Orca
    Worker -->|検証済み応答| App
~~~

Firestoreを読み書きするのはReactアプリのRepository。Firebase Hostingは静的配信を担当し、OrcaRouterとFirestoreの直接接続はない。全ペア採点・部屋最適化はReactアプリ内のTypeScript処理であり、独立したクラウドサービスではない。生成済みPNGは旧説明用で、サービス接続と今回仕様の正本はこの図と確定設計書とする。

## 今回の業務フロー（追加部分を含む目標）

~~~mermaid
flowchart TD
    Login[施設ログイン・スタッフ選択]
    Invite[招待URL/QR発行<br/>既存発行者契約を維持]
    Intake[飼い主入力<br/>健康・社会化・行動6問・自由記述]
    AI[Worker / OrcaRouter<br/>7軸・根拠・信頼度]
    Profile[受付・分析・プロフィール保存]
    Select[対象日・当日対象犬を明示選択して保存]
    Rooms[施設別部屋設定を保存]
    Pair[選択対象の全ペア採点<br/>既存信号 + AI 7軸最大18点 → 100点<br/>適用状態・内訳・hard block]
    Plan[部屋割り最適化]
    Proposed[最新proposedを保存<br/>旧proposedはsuperseded]
    Review[選択中スタッフが承認/却下]
    Audit[操作監査保存<br/>担当・日時・理由・元案]
    Manual[スタッフ手動観測の保存]
    Login --> Invite --> Intake --> AI --> Profile --> Select
    Login --> Rooms
    Select --> Pair
    Rooms --> Plan
    Pair --> Plan --> Proposed --> Review
    Review -->|confirmed / rejected| Audit
    Select -->|day_saved| Audit
    Rooms -->|rooms_saved| Audit
    Proposed -->|recalculated| Audit
    Manual -->|再計算| Pair
~~~

健康・社会化・実モック6問/7軸、日付付き対象、施設別部屋設定、4状態遷移と監査は実装・ローカル統合検証済み。手動部屋編集と5分類は含めない。本番資格情報が必要な公開認証後E2Eだけは未実施。

7軸は表示・保存だけでなく相性100点の最大18点へ使う。両犬に7軸が揃う場合だけ適用し、旧データは既存計算へ戻す。全ペア、最適化、提案保存、再表示で同一のscoreと適用内訳を共有し、hard blockは独立して適用する。
